1. What this does

Before: when someone changed something in Notion, the app did not know. Someone had to press Sync, or wait for the daily sync.

Now: when something changes in Notion, Notion sends a message to the app right away. The app updates only that one record. Nobody needs to press Sync for these changes.

Notion databaseWhat the app updates
OrdersOnly the Finny Status of the matching proforma slip (matched by order number). No other slip field is changed.
Vehicle MasterThat vehicle's details. A vehicle that is new in Notion is added to the app.
Product MasterThat product's details, including its photo. A product that is new in Notion is added to the app.
In simple words
It works like a doorbell. Instead of checking Notion every few minutes, Notion "rings" the app the moment something changes.

2. How it works

1. Change in NotionSomeone edits an order, vehicle or product.
→
2. Notion calls the app"This page changed" is sent to the app's webhook address.
→
3. Security checkThe app checks the message really came from Notion.
→
4. UpdateThe app reads that page from Notion and updates only that record.

The details

  • Only which page changed is sent. Notion's message does not include the new values, so the app reads that one page back from Notion and then updates its own record.
  • Security: every message from Notion carries a signature made with a secret token. The app recalculates it and rejects anything that does not match, so nobody else can send fake changes.
  • Quick edits are grouped: several edits to the same page within 3 seconds are handled as one update.
  • No loops: when the app itself sends a status to Notion, Notion reports that change back. The app sees the value already matches and does nothing.
  • Speed: changes usually arrive within a minute. Notion allows up to 5 minutes.
  • If the server is down: Notion retries each message up to 8 times over about 24 hours, so a short outage does not lose changes.

3. Before you start

  • The app is reachable on the internet over https. Notion cannot reach localhost. For testing on a PC, use a tunnel (step A).
  • Admin access in Notion to the connection (integration) the app already uses.
  • Access to the server's .env file and permission to restart the server.
  • An admin login to the KM Finny app, to open the status page.

4. Setup, step by step

A

Get a public https address for the app

Live server: use the real domain, for example https://yourdomain.com.

Testing on a PC (the app runs on port 5000), use one of:

  • VS Code: open the Ports panel → Forward a Port → enter 5000. Then right-click the port → Port Visibility → Public. Copy the https address shown.
  • ngrok: run ngrok http 5000 and copy the https address.
Important
A VS Code port is Private by default — Notion cannot reach it until it is set to Public. A tunnel address also changes each time it restarts, so it is only for testing.
B

Give the connection access to the three databases

Open each database in Notion: Orders, Vehicle Master and Product Master. Click ••• (top right) → Connections and make sure the app's connection is listed. Notion only sends changes for pages the connection can see.

C

Create the webhook subscription

  1. Go to https://app.notion.com/developers/connections and open the app's connection.
  2. Open the Webhooks tab → + Create a subscription.
  3. URL: the address from step A followed by /api/webhooks/notion 
    https://yourdomain.com/api/webhooks/notion
  4. Events: select page.created, page.properties_updated, page.content_updated, page.undeleted, page.moved and page.deleted. Then create it.
D

Verify the subscription

  1. Right after creating it, Notion sends a one-time verification token to the app. It is printed in the server log, in a block starting with Verification token received. Copy the value that starts with secret_.
  2. Back in Notion's Webhooks tab, click ⚠️ Verify (bottom left), paste the token, and click Verify subscription.
Keep it secret
This token proves messages really come from Notion. Do not share it in chat, email or screenshots.
E

Save the token on the server

Add this line to the server's .env file, then restart the server:

NOTION_WEBHOOK_VERIFICATION_TOKEN=secret_xxxxxxxxxxxxxxxx

Until this is set, the app receives Notion's messages but ignores them.

F

Test it

  1. In Notion, change Finny Status on a test order.
  2. Wait up to a minute (at most 5).
  3. Open Proforma Slips in the app — the status should show the new value.
  4. Change a field on a vehicle and on a product the same way, and check Vehicle Master and Product Master.

You can also check the status page (section 6).

G

Move from testing to live

If you tested with a tunnel: in Notion, edit the subscription URL to the live domain, then repeat steps D and E — the new URL gets its own token.

5. Server settings (.env)

These are the settings the webhook uses. The last two are new; the others already exist for the Notion syncs. Never put real secret values in shared documents.

SettingWhat it is for
NOTION_INTEGRATION_SECRETLets the app read pages from Notion (already in use).
ORDER_DATABASE_IDTells the app which Notion database is Orders (already in use).
NOTION_VEHICLE_DATABASE_IDWhich database is Vehicle Master (already in use).
NOTION_INVENTORY_DATABASE_IDWhich database is Product Master (already in use).
NOTION_WEBHOOK_VERIFICATION_TOKEN (new)The secret token from step D. Required — without it all messages are ignored.
NOTION_WEBHOOK_STATUS_URL (new, optional)Link opened by the Open status button in Settings. Example: https://yourdomain.com/api/webhooks/notion/status

After changing .env, restart the server so it picks up the change.

6. Check that it works

In the app, go to Settings → Notion Webhook Status → Open status (admins only). It opens a page listing the setup and the last 100 changes Notion sent.

LineMeaningYou want to see
tokenConfiguredIs the secret token saved on the server?true
databasesConfiguredDoes the server know the three database IDs?all three true
lastVerificationAtWhen Notion last sent its verification (step D)a date after setup
pendingPagesChanges waiting a few seconds before being appliedusually 0
recentActivityThe last 100 changes, newest first, and what happened to eachsee below

What each result means

ResultMeaning
updatedThe change was saved in the app. For orders it shows the order number and new status, e.g. updated (#100459 → DISPATCHED).
createdA new vehicle or product was added.
unchangedThe app already had that value — nothing to do.
ignoredNothing to do: a page from another database, a page moved to trash, or the token is not set.
waitingA full manual sync was running; the change will be retried in 30 seconds.
rejectedThe signature did not match — the message did not come from Notion, or the token is wrong.
errorSomething went wrong; the reason is shown next to it.

8. Going live checklist

  • Subscription URL is the live https domain + /api/webhooks/notion
  • Subscription is verified in Notion
  • NOTION_WEBHOOK_VERIFICATION_TOKEN is set on the live server, and the server was restarted
  • The connection has access to Orders, Vehicle Master and Product Master
  • A test status change appears in the app, and the status page shows updated
  • NOTION_WEBHOOK_STATUS_URL points to the live domain (optional)

9. Good to know

  • For orders, only Finny Status is updated. Other slip fields still come from Import / Sync from Notion.
  • Deleting in Notion does not delete in the app. A page moved to trash is only noted on the status page.
  • The Sync buttons and the daily sync still exist as a backup in case a change is ever missed. They can be turned off later, once the webhook has been confirmed working live.
  • The status page keeps the last 100 changes in memory — it starts empty again after a server restart.
  • Vehicles and products use exactly the same rules as the Sync buttons, so a webhook update and a manual sync always give the same result.
